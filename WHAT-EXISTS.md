## 4. BROKEN / GAP LIST — the honest one

1. **In-app Ollama download — FIXED in code 2026-10-18, not yet proven against the real 1.47 GB file.** (The RUNNING problem was fixed earlier the same day: the app starts your installed Ollama at boot, so it no longer needs the downloader to have a door.) The unpack step used pack-sized limits (200 MB/file, 400 MB total) against an archive measured at **1.47 GB compressed, 87 entries, 1.94 GB unpacked, biggest file 692 MB** — so the app downloaded the official zip in full and then refused to unpack it, with a sentence that read like the publisher's fault. `RUNTIME_ZIP_LIMITS` (512 files / 1.5 GB per file / 4 GB total) now applies to a runtime zip only; theme and skill packs keep the strict caps, and a hostile archive is still refused at 4 GB. The download also streams now, so the progress line moves while bytes arrive and the 2.5 GB cap is enforced in flight rather than after the whole offer has landed in memory — with one buffer filled in place, because gathering chunks would hold a 1.47 GB archive twice over on your 8 GB machine. Pinned by `tests/runtime-zip-limits.test.ts`, which carries the measured shape as declared central-directory sizes (the gate that actually refused it), and `tests/download-stream.test.ts`. **What is still unproven: unpacking the genuine 1.47 GB file on your machine.** A fixture declares the sizes; it does not inflate 1.94 GB. Until you have run it, `winget install Ollama.Ollama` remains the route that is known to work — the app finds it automatically.
2. **Store phases 2–3 don't exist** (Claude Code plugin marketplaces; agy catalog). Design is final (`ENGINE-STORES-DESIGN.md`); awaits your go; needs a live probe of `claude plugin marketplace` on your machine before any claim.
3. **agy signed-in live turn — never driven.** The wire is built and unit-proven; the real thing is not. **agy-not-found on your machine — fixed in code 2026-10-18:** "Point to the exe…" on the agy card, pick `agy.exe` once, it persists and beats every probe; if the auto probe still misses, the pointed exe is used. Awaiting your machine.
4. **The full acceptance checklist is unrun** — real turn → Allow/Deny → Restore → always-loaded → startup → extension capture, by YOU, on the TUF A15, on the newest build. This is the actual bar for "works".
5. **CI has two known flakes** (fixed-sleep races). One is root-fixed (`engine-media`). Protocol if one shows: identical commit green on the other branch ⇒ re-run failed jobs before suspecting code.
6. **Unsigned installer** — Windows shows "unknown publisher". No certificate exists; stated, not hidden.
7. **The two real-machine bugs you reported 2026-10-18 — FIXED IN CODE, pending your machine.** ① App found no Ollama and the desktop app quits fully, so you had to run `ollama serve` by hand → now the app starts your installed copy at boot (`%LOCALAPPDATA%\Programs\Ollama\ollama.exe` → PATH → staged copy), the Ollama card has "Start the brain door", and the honest answer names which copy started. ② agy not found → "Point to the exe…" on the agy card persists your pick in `userData/engine-binaries.json` and it beats every probe/launch; "Use automatic detection" undoes it. 8. **Audio is not transcribed, and PDF/Office are not parsed — deliberately, and it needs your call.** The front door names each one and says why, rather than guessing at contents. Doing it for real means one of two things, and neither is mine to pick quietly: a local model (a whisper-class brain you install, which costs disk and VRAM on a 4 GB card), or a dependency (a PDF/Office parser in the installer, which grows it past 96 MB and adds supply-chain surface to an app whose whole promise is local-first). Say which and it lands.
9. **The watch-mode fire was broken and is now fixed in code.** A native timer can wake a millisecond before the wall clock crosses the quiet boundary; the gathered batch was cleared before the decision, the decision answered "debounce", and nothing re-armed — so a real file change was discarded forever. `tests/watch-fire.test.ts` failed deterministically on this (its 5-second poll guard ran the full five seconds and never saw a send), and passed again when a single `console.log` slowed the timer by one millisecond, which is the fingerprint of a boundary rather than a logic error. It now re-arms for the remaining quiet; no gate was bypassed. Pinned by `tests/watch-boundary.test.ts` with a frozen clock, which fails on the old code with "expected [] to have a length of 1 but got +0".
