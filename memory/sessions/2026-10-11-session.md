## 22:55 — the preview broke, and it was my fault for how I tested

> preview isn't working

The page loaded but every API call failed. Both layers adopted from 01199af1
refuse an `Origin` that is not loopback:

- vault API → "Origin is not authorized for this local vault API."
- proxy policy → "Cross-origin API requests are not authorized."

Correct on the user's machine; fatal behind a forwarded preview host.

**The mistake:** when I verified the endpoints after the port, I used `curl`
without an `Origin` header. A browser always sends one on these calls. So my
checks passed while the actual thing was 403ing. If a layer's whole job is
deciding who may call it, testing it without the identifying header tests
nothing.

Fixes: the vault API already had an `ALLOW_PREVIEW_ORIGINS=1` hatch for
`*.e2b.app` that I had not set. `proxy-policy.cjs` had none, and its strict
`origin.host === host` comparison also breaks when the proxy does not forward
the public host — so I gave it the same env-var hatch, defaulting to the strict
same-origin check. Both off by default; non-preview origins still refused.

Verified with and without `X-Forwarded-Host`, and confirmed
`https://evil.example.com` is still denied.
