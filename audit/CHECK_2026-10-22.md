## Findings

### Must fix

1. **The reader's three ffmpeg commands still never run** (`src/main/media/service.ts:186, 196, 212`)
   - **What this is:** The reader asks ffmpeg for loudness, pauses and scene cuts. You reworked loudness into
     one-second windows and added 60-second transcript intervals.
   - **Problem:** The output target is still `file=pipe\:1`, which ffmpeg 4.2.2 and 7.0.2 reject. On a 75-second video
     with 4 cuts the reader returned 0 cuts, no loudness and no pauses (measured). Your README now says the map
     holds "interval-level recognized-word pace/RMS/pause measurements" and "the bounded two-frame-per-second
     scene-change index". Neither is true on a real ffmpeg. With only that argument changed, your new code works:
     one-second RMS windows, 4 pause intervals totalling 20 s, cuts at 30, 45 and 60 s.
   - **Fix:** Change `file=pipe\\:1` to `file=-` in the three places, and show ffmpeg's own error text in the evidence
     when a pass fails.
   - **If we skip it:** The AI never gets pause or scene data, and the README breaks your first rule, "Never invent a
     capability".

2. **The Skill sends the AI to three tools that do not exist** (`src/shared/lib/videoEditingSkill.ts:67-68`)
   - **What this is:** After the owner approves "Inspect verified preview", the Skill says to read the new evidence map
     with `oddbrain_evidence_inventory`, `oddbrain_evidence_search` and `oddbrain_evidence_expand`.
   - **Problem:** No code defines those names. The review server offers `oddbrain_video_sources`,
     `oddbrain_video_evidence`, `oddbrain_video_locate` and `oddbrain_video_evidence_expand` (measured, tool list). The AI
     will get "unknown tool" at the step that closes the improve loop.
   - **Fix:** Replace the three names with the four real ones.
   - **If we skip it:** The preview inspection you built works, and the AI cannot read what it produced.

3. **A failed YouTube download still throws itself away** (`src/main/video/service.ts:737`)
   - **What this is:** yt-dlp fetches video and audio separately and joins them with ffmpeg.
   - **Problem:** Without ffmpeg on PATH it leaves two files and prints a path that does not exist. OddBrain reports
     `ENOENT`, claims "the completed source remains at" that path and deletes the staging folder (measured, real yt-dlp
     2026.08.19). The new durable intake does not help, because the failure happens before the intake exists.
   - **Fix:** Pass `--ffmpeg-location` (the media settings already hold an ffmpeg path), cap the height at 1080 p, check
     the printed file exists, and keep the staged files when joining fails.
   - **If we skip it:** On a PC without ffmpeg on PATH every YouTube link fails and costs a full download.

### Should fix

4. **Overview frames cover only the first third of a video** (`src/shared/lib/videoStudio.ts`, `adaptiveFramePoints`)
   - **What this is:** The reader keeps up to 12 frames (one per 2 minutes, minimum 3). Where no scene cut is found it
     fills the rest with evenly spaced "overview" frames.
   - **Problem:** The fill loop takes the first 12 points of a 36-point grid, so they all land in the first third.
     Measured: a 60-minute lecture with no cuts gets 12 frames between 97 s and 1,168 s and none after. With two cuts
     found, the last frame is at 50%. Lectures, interviews and talking heads often have no cuts.
   - **Fix:** Space the missing frames over the whole duration, for example `duration * (k + 0.5) / missing` for each
     missing slot. About three lines.
   - **If we skip it:** The AI believes it has "broad coverage" of a long talk while two thirds of it have no frame.

5. **The AI is still not given the command format** (`oddbrain_edit_plan_propose`)
   - **What this is:** The AI writes batch commands such as `insert`, `clip_fade`, `audio_duck` and `range_cut`.
   - **Problem:** The plan schema is `{"type":"object"}` and the Skill names `title_create` only. Upstream publishes a full
     schema for each command in its `desktop_batch` tool. The AI now has real IDs and still has to guess field names.
   - **Fix:** Forward the `commands.items.oneOf` schema from the live `desktop_batch` tool as the plan's schema.
   - **If we skip it:** Plans fail at preflight or at apply on field names, one retry at a time.

6. **The evidence file still fills after 42 one-hour videos** (`src/main/video/service.ts:603`, `src/main/recoverableJson.ts:8`)
   - **What this is:** All evidence lives in one file, with each transcript stored three times.
   - **Problem:** Measured with a reader-shaped result (60 one-minute sections): 184 KB per video, and the 43rd is
     refused with "Store exceeds the 8 MB recovery limit". Word timestamps will lower the number.
   - **Fix:** Store each transcript once in the per-video folder the code already makes, and keep a summary in the index.
   - **If we skip it:** After a few weeks of daily videos, new videos download and cannot be read.

7. **Backup and memory search still freeze the app** (`src/main/vault/backup.ts:44-66`, `src/main/vault/recall.ts:18-20`)
   - **What this is:** Both use blocking file calls on the main thread.
   - **Problem:** Measured: backing up 1 GB stops the app for 4.0 s, and one search at 3,000 notes stops it for 0.4 s.
     Your backup now also copies the video evidence and frames, so a creator's backups get bigger.
   - **Fix:** Async file calls with a yield between 1 MB chunks for backup, and a worker thread for search.
   - **If we skip it:** Windows usually marks a window "Not Responding" after about 5 seconds, so large backups look like crashes.

8. **Library licences and units** (`src/main/video/service.ts`, Openverse search)
   - **What this is:** The owner approves one exact result before download.
   - **Problem:** CC BY-NC and CC BY-ND results can still be approved, and the Openverse request carries no `license_type`
     filter (measured). Openverse audio duration is milliseconds and is shown as seconds (180000 for a 3-minute track).
   - **Fix:** Add `license_type=commercial,modification` to the Openverse request and divide audio duration by 1,000.
   - **If we skip it:** You may publish or sell a video that contains music you were not allowed to use that way.

9. **No automatic reconnect to the editor** (`src/main/video/service.ts`, `nativeConnection`)
   - **What this is:** The editor drops an idle session after 30 minutes.
   - **Problem:** OddBrain keeps the dead session, and every read, plan review and frame capture fails with "HTTP 404" until
     the owner presses Test connection (measured).
   - **Fix:** On 404, initialise again and retry reads once. For edits, reconnect and require a fresh state read.
   - **If we skip it:** A coffee break ends the editing session.

10. **Two functions keep growing** (`src/main/index.ts:361`, `src/main/video/service.ts:144`)
    - **What this is:** `registerBridges` registers all 273 handlers. `createVideoStudioService` holds the whole video feature.
    - **Problem:** Counted: 2,053 and 1,086 lines, up from 1,995 and 676. Nobody can read either in one sitting.
    - **Fix:** Split by job, for example render, evidence and library out of the video service, with shared variables in a
      small `deps` object.
    - **If we skip it:** The next feature adds 200 more lines to the same function.
